# What is ChromaDB?

ChromaDB is an **open-source vector database** built specifically for AI applications.

Instead of storing data in rows and columns like SQL databases, it stores:

- Documents
- Embeddings (vectors)
- Metadata
- IDs

It allows semantic search using vector similarity.

Think of it as:

```
PDF
 ↓
Chunks
 ↓
Embeddings
 ↓
ChromaDB
 ↓
Similarity Search
 ↓
LLM
```

---

# Why ChromaDB?

Traditional Database

- Search by exact keyword
- SQL
- Structured data

ChromaDB

- Search by meaning
- Semantic similarity
- AI applications

Example

Search:

> "Machine learning"

It can also return:

- AI
- Deep Learning
- Neural Networks

Even if those exact words aren't present.

Each document requires a unique ID.

Example

```python

```

```
Python

Java

Finance

Medical
```

You only want AI documents.

Example


# Interview Preparation – ChromaDB & Vector Databases

## Q1. What is a vector database?

### Answer

A **vector database** is a specialised database designed to store **vector embeddings** and efficiently perform **similarity searches**. Unlike relational databases, which search using exact values or indexes, a vector database retrieves information based on **semantic similarity** (meaning) between vectors.

**Key Points**
- Stores vector embeddings generated by embedding models.
- Optimized for nearest-neighbour search.
- Used in AI applications such as RAG, semantic search, and recommendation systems.
- Examples: ChromaDB, Pinecone, Weaviate, Milvus, Qdrant.

---

## Q2. Why can't we use MySQL?

### Answer

Relational databases like **MySQL** are excellent for **structured queries**, exact matches, joins, and indexed searches. However, semantic search requires **nearest-neighbour search** across **high-dimensional vectors**, which relational databases are not designed to optimise.

**Comparison**

| MySQL | Vector Database |
|--------|-----------------|
| Exact matching | Semantic similarity |
| SQL queries | Vector similarity search |
| Uses indexes | Uses vector indexes (HNSW, IVF, etc.) |
| Structured data | Embeddings and AI data |

---

## Q3. What is a collection in ChromaDB?

### Answer

A **Collection** in ChromaDB is similar to a **table** in a relational database. It stores:

- Documents
- Vector embeddings
- Metadata
- Unique IDs

Each collection groups related documents together, making them easier to manage and search.

---

## Q4. What is Top-K retrieval?

### Answer

**Top-K retrieval** is the process of returning the **K most similar documents** for a given query based on vector similarity.

For example:

If **K = 3**, the vector database returns the **three most relevant documents**.

Example:

```
Query:
"What is Machine Learning?"

↓

Top 3 Results

1. AI Basics
2. Machine Learning Guide
3. Deep Learning Overview
```

---

## Q5. Why is Top-K important?

### Answer

Providing multiple relevant documents gives the LLM **better context**, resulting in more accurate and reliable responses.

Benefits of Top-K retrieval:

- Reduces hallucinations.
- Improves answer accuracy.
- Provides richer context.
- Increases the likelihood of retrieving the correct information.

Choosing the right value of **K** is important:
- Too small → May miss relevant information.
- Too large → May introduce irrelevant context and increase token usage.

---

## Q6. Where does ChromaDB fit in RAG?

### Answer

In a **Retrieval-Augmented Generation (RAG)** pipeline, ChromaDB acts as the **vector database**.

It stores document embeddings and retrieves the most relevant documents before they are sent to the LLM for generating the final response.

### RAG Workflow

```
Documents
    │
    ▼
Chunking
    │
    ▼
Embedding Model
    │
    ▼
ChromaDB (Vector Database)
    │
    ▼
Top-K Retrieval
    │
    ▼
Relevant Context
    │
    ▼
Large Language Model (LLM)
    │
    ▼
Final Answer
```

**Key Responsibilities of ChromaDB in RAG**

- Stores vector embeddings.
- Performs semantic similarity searches.
- Retrieves the Top-K relevant documents.
- Supplies contextual information to the LLM.
- Helps reduce hallucinations by grounding responses in retrieved data.
